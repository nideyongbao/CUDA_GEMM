# CUDA Core 用例 ncu 剖析汇总

（Tensor Core 那半见 `../tensor_core/SUMMARY.md`；本表是 CUDA core 的 FP32 / BF16 阶梯。）

- 工具：`ncu --set full`（需 GPU 计数器权限 → `sudo /usr/local/cuda/bin/ncu`），脚本 `profiling/cuda_core/run_ncu.sh`。
- 剖析尺寸：**2048³**（`-s 1 -c 1`，跳过第 1 次 launch、剖析第 2 次 warmup），`-k regex:<内核>` 只抓目标 `__global__`。
- 驱动：FP32 `kernels/cuda_core/bench <id>`、BF16 `kernels/cuda_core/bench_bf16 <id>`（内部 2 warmup + 10 timed）。
- 完整报告：`profiling/cuda_core/cc_*.ncu-rep`（UI 打开）+ `profiling/cuda_core/cc_*.details.txt`（文本全量）。
- **GFLOPS@2048³** 由 ncu 单次 launch 的 Duration 反推（`2·2048³/dur`），非 headline 数（headline 用 4096³，规模越大利用率越高）。

## 一句话结论

- **CUDA core 的优化主线是 ILP 取代 TLP**：占用率从 naive 的 ~99% 一路降到 doublebuffer 的 ~21%，性能反而从 3.4 → 21.5 TFLOPS。靠寄存器/共享内存分块抬高算术强度，把 `warp cyc/issue` 从 **36→4.6**（每次发射的平均阻塞周期），用更少的 warp、更密的指令吃满 SM。cublas（`sm80_xmma_gemm`）正是极致：占用率仅 24%，却 Compute 88% / SM Busy 90% / cyc/issue 4.35。
- **阶梯读法**：naive/smem 阶段是**访存指令瓶颈**（L1/TEX 76→94%、cyc/issue 高、靠满占用率硬扛）；1D→2D 分块把 cyc/issue 砍到个位数；向量化(float4)再降总指令数；warptile 单独上会**寄存器爆到 211、占用率掉到 11%** 反而变慢，必须叠加向量化(warptile_vec)才回血；去 bank conflict 把 L1/TEX 压力从 ~85% 降到 ~57%；double buffer 用双缓冲重叠搬运/计算，拿到手写最高 **~21.5 TFLOPS（≈ cublas 的 94%）**。
- **FP32 vs BF16**：两条阶梯几乎同形；BF16 因数据搬运减半，doublebuffer 反超 FP32（22.2 vs 21.5 TFLOPS）；naive 例外（每元素转换开销大，反而更慢）。
- 注：本表为 **2048³** 的单次 launch 剖析值；headline 吞吐请用 4096³（见 `docs/H20复现结论`）。
