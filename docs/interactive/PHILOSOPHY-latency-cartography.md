# Latency Cartography（延迟制图学）

> 一套生成式美学宣言 —— 为「CUDA core GEMM 优化阶梯」的可交互可视化而写。
> （algorithmic-art skill 的第 1 步：先立哲学，再用代码表达。）

## 运动名称

**Latency Cartography —— 延迟制图学**

把 GPU 上那条看不见的「延迟地形」画出来：数据是旅人，内存层级是海拔，吞吐量是当每个旅人在等待时都能找到事做之后，自发涌现出来的洪流。

## 哲学

现代 GPU 的真正敌人从来不是「算得不够快」，而是「等得太久」。一次远程内存访问要熬上数百个周期，而一次乘加只要一个周期。于是整部优化史，本质上是一张**藏匿延迟的地图**：把反复用到的数据一级一级搬近（global → shared → register），并在不得不等待的缝隙里塞进足够多互相独立的工作，让流水线永不空转。这套可视化要让这张地图**活起来**——不是静态示意图，而是一个随时间演化、每一帧都在搬运与计算之间做权衡的活系统。

美在于**流动**。明亮的数据包沿着内存层级向上攀爬，慢的航段（DRAM）拉得很长、暗而迟疑，快的航段（寄存器）短促而炽亮；这种长度与色温的对比，本身就把「延迟」这个抽象量变成了肉眼可读的距离。当算法还朴素时，成千上万个旅人同时挤向最远最暗的那一层，调度器一片猩红的「等待」——画面是拥堵、是焦灼。随着优化推进，搬运被复用摊薄、独立的乘加排成长队填满每一个空窗，红色褪去，洪流变得顺滑——**秩序从拥堵中涌现**，这正是整套美学的叙事弧线。

这套系统要表达一个反直觉、却贯穿全程的主题：**少即是多（ILP 取代 TLP）**。早期靠塞满 warp（高占用率）硬扛延迟，画面里塞满旅人却各自呆立；而真正的高手反其道而行——旅人变少，但每个旅人手里都攥着一长串互不依赖的活，等待时随手就能补位。占用率一路从 99% 跌到 24%，吞吐量却从 3.5 一路涨到 25 TFLOPS。可视化必须让观者亲眼看到这条**反向曲线**：拥挤的衰退与稀疏的繁荣同框，那一刻的认知冲击就是这件作品的灵魂。

这是一件**精雕细琢、历经无数次推敲**的算法作品。每一个缓动曲线、每一束数据包的色温、每一条流水线 token 的间距，都应像出自一位在计算美学与体系结构之间浸淫多年的大师之手——既要有工程师对硬件真相的苛刻忠实（所有数字都来自 H20 实测），又要有艺术家对节奏与留白的拿捏。它不该看起来「能跑就行」，而该看起来**是被打磨过千百遍的、专家级的实现**：克制的配色、呼吸般的动画节奏、信息密度与可读性之间反复权衡后的平衡。

它还必须是**新手友好**的。每一个必要的名词——warp、shared memory、bank conflict、occupancy、ILP——都先于使用之前，用最朴素的比喻交代清楚它的背景与目标，绝不堆砌术语吓退初学者。复杂的真相用简单的画面承载：一根变粗的箭头讲清 float4，两块乒乓切换的缓冲讲清 double buffering，三十二根撞向同一格子的线讲清 bank conflict。**思想要简单直观，画面要一眼看懂，而背后的工程深度要经得起专家推敲**——这三者的同时达成，正是这件作品追求的至高匠艺。

## 概念种子（埋在算法里的隐线）

整条阶梯只讲一件事：**latency hiding（藏延迟）**。所以可视化的隐藏母题是「等待与填补」——画面永远在问同一个问题：*此刻，有没有活可以填进这段等待？* 朴素版的答案是「没有，大家一起干等」；登顶版的答案是「有，独立的乘加和预取的下一块永远排着队」。观者哪怕不懂 CUDA，也会本能地感到画面从「焦灼的等待」走向「从容的流动」——而懂行的人会会心一笑：这正是 GPU 性能工程的全部秘密。

## 表达方式（交给实现的指引）

- **活的算法，而非静态图**：每一阶段都是一个随时钟演化的循环动画——加载相 → 计算相 → 暴露瓶颈 → 下一阶段修复它。
- **统一的视觉语言**：三层内存阶梯（寄存器/共享/全局）作为贯穿全程的骨架；数据包、箭头粗细、流水线 token、调度器色温作为可复用的语汇，让观者看到的是**同一个系统的演化**，而非十张无关的图。
- **种子化的有机扰动**：粒子抖动、数据包微光由随机种子驱动，同一种子永远复现同一节奏——可探索，亦可复刻。
- **重点突出**：每一阶段画面里只主推一个核心洞察（一个被修复的瓶颈），细节交给旁边的文字面板；动画负责「直觉」，文字负责「精确」。
- **忠于实测**：所有 GFLOPS、占用率、cyc/issue、bank conflict 计数均来自 H20（Hopper, CC 9.0）真机 `ncu --set full`，不杜撰。
